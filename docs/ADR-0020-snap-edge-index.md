# ADR-0020 — オブジェクトスナップのエッジ索引

- Status: Accepted
- Date: 2026-09-23
- 関連: ADR-0009 (id 索引 / グリッド共有 choke point), ADR-0019 (同パターンのメモ化)

## 問題

`objectSnap` (move ドラッグ) と `resizeSnap` (resize ドラッグ) は**毎
pointermove** に `state.shapes` を全走査してスナップ対象のエッジリスト
(各 bbox の左/中央/右 × 上/中央/下) を構築していた — 5000 図形で
~1.1ms/イベント (ADR-0019 適用後でも走査自体が残る)。

スナップは「最も近い許容範囲内のエッジ」だけを要するので、全走査は
ほぼ無駄 — 古典的な sorted-list + binary search の適用箇所。

## 決定

- `_snapIndex(kind, key, exclFn)`: 全シェイプ (除外集合以外) の
  エッジ+中央座標を x 軸 / y 軸それぞれソートした索引。`'move'` と
  `'resize'` の 2 スロットで共有。
- 有効性は **`_gridVer`** (`_invalidateGrid` でインクリメントする変異
  カウンタ、新設) + 呼出側の除外キーで判定。シェイプの変異はすべて
  `_invalidateGrid` を通るため、ドラッグ中のリモート op を含めて
  自動的に再構築される — 従来の毎イベント再構築と同等の鮮度。
- 照会は `_snapNear(arr,v,tol)` の二分探索 + ウィンドウ走査 — O(log n)。
- `snapBox` の公開シグネチャ (mov,targets,tol) はテスト契約なので維持し、
  内部を `_snapBoxIdx(mov,idx,tol)` (索引版) + `_mkSnapIdx(targets)`
  (リスト → 索引) に分解。move/resize の呼び出しは索引経路へ。

## 却下した案

- **一時キャッシュを `ptr` に置く**: ジェスチャ状態への直結は動作するが、
  リモート op によるドラッグ中の変異を検知できない。`_gridVer` 連動なら
  既存の無効化経路に乗れて正確。
- **空間グリッド `_grid` 自体をスナップに再利用**: グリッドは 200wu セル
  ベースで「近傍」しか返さない — スナップは縦方向全域の x エッジ整合が
  必要なので、セル走査では遠距離エッジを取りこぼす。ソート済みエッジ軸は
  本質的に違うデータ構造。

## 検証 (実施済)

- `node test.mjs` 全緑: snapBox の既存テスト + 新規 (索引 vs 総当たりの
  60 ケース一致、`_gridVer` / 除外キーでの再構築)
- 実ブラウザ (pen 4000 + rect 1000): resizeSnap **1.08ms → 0.002ms**
  (≈540×)、総当たりとの 40/40 結果一致
