# ADR-0005 — スケッチ整形 (beautify: ペンストロークの図形認識)

- Status: Accepted (implemented)
- Date: 2026-07-01
- 関連: 製品判断「Board は scratchpad(単独体験)を選択」(CLAUDE.md「100点への距離」2026-07-01)、
  `docs/research-improvements.md` item M ($1/$Q unistroke recognizer), G (スケッチ認識/AI項目)

## なぜ (Context)

Multi-page/コラボ機能を「workspace」寄りとして対象外にする製品判断を確定させた(§3.9)。
代わりに「単独体験の研磨」に投資する方針とし、その具体策の一つとして README ロードマップの
AI 項目(v1.4 に記載のあった "AI shape recognition")の現実的な着地点を探した。

`docs/research-improvements.md` item G/M が提示する通り、フル ML(WASM/BYOK)は依存が重く
単一HTML原則と緊張関係にある。一方 **$1/$Q Unistroke Recognizer**(Wobbrock et al.)は
テンプレートマッチのみで実装 100行未満・依存ゼロ・97%程度の認識率が報告されている。ただし
$1/$Q はテンプレート点群との DTW 的マッチングを要し、Board が実際に必要とするのは
「line/rect/ellipse という**具体的な描画ツールへの変換**」のみ(triangle 等 Board に無い
図形は認識しても変換先が無く無意味)。そこで $1/$Q そのものではなく、**同じ思想(依存ゼロ・
決定的・幾何ヒューリスティック)で Board の実図形3種に特化した軽量版**を実装する。

## 何を (Decision)

1. **`recognizeStroke(pts)`**: 純粋関数。ペンストロークの点列を受け取り、`line`/`rect`/
   `ellipse` のいずれかに自信を持って一致すれば `{type,...幾何パラメータ}` を、しなければ
   `null` を返す。判定はサイズ非依存の相対閾値(+絶対フロア)で、$1/$Q と同じ「位置・拡縮
   不変」の精神を保つ:
   - **line**: 始点→終点の弦からの最大垂直距離が弦長の8%以下、かつ経路長が弦長の1.35倍以下。
   - **rect**: 全点が(始点と終点が近い=閉じたループの場合のみ判定)軸並行バウンディングボックス
     の4辺のいずれかに、短辺の12%以内で密着。
   - **ellipse**: 重心からの距離をバウンディングボックスの半幅/半高で正規化し、その変動係数
     (標準偏差/平均)が0.22以下。
   - 三角形やフリーハンドの複雑な図形は意図的に非対応(Board に変換先の図形が無いため)。
2. **`doBeautify()`**: 選択中の pen シェイプそれぞれに `recognizeStroke` を適用し、認識できた
   ものだけを `type`+幾何パラメータで置き換える。**新しい op 型を追加せず**、既存の
   `case 'style': case 'resize': case 'align':` の汎用「複数シェイプ絶対パッチ、単一 undo」
   機構に `case 'beautify':` として相乗り(`_apply` の実装は完全に共有、`Object.assign` が
   古いフィールド(`pts` 等)を残すが `type` が変わるため描画/hit-test/bbox はすべて無視する
   — 空いたフィールドは undo で type が戻れば再び有効になる無害な残留データ)。
   ロック済みシェイプは対象外(既存パターンと同じガード)。1つも認識できなければトーストで
   通知するのみで履歴には残さない(空振りは undo 対象にしない)。
3. **ローカル専用**: `REMOTE_OPS` に `'beautify'` を追加しない。`replace`/`clear` と同じ
   「ブロードキャストはされるが受信側の allow-list で無視される」パターン(実害なし、
   帯域の無駄のみ — 既存踏襲)。ペン描画の変換はローカル UI 判断であり、リモート同期の
   対象にする必然性がない(共同編集相手のペン画を勝手に矩形へ変換すると混乱を招く)。
4. **キー割当**: `Alt+B`("Beautify")。選択中の pen シェイプに対して実行。

## 代替案 (Alternatives)

- **$1/$Q をそのまま実装(テンプレートDB方式)**: line/circle/rectangle/triangle 等を
  テンプレート点群と照合。Board の実図形(rect/ellipse/line のみ)に対して過剰な一般性で、
  テンプレート点群のデータ量・DTW 実装が本 MVP には不釣り合い。却下(将来 triangle 等を
  Board 自体の図形として追加する場合は再検討の価値あり)。
- **ML ベース(WASM/BYOK)**: 依存が重く、`docs/research-improvements.md` item G 自身が
  「offline-first を壊さない任意機能」と位置付ける将来拡張。今回は却下。
- **自動整形(描画完了時に確認なしで即座に変換)**: 誤検出時にユーザーの意図しない変換を
  強制する。既存の「明示的なキー操作でユーザーが選ぶ」UX パターン(フォーマットペインター
  等)と一貫させ、確認的な `Alt+B` 明示実行を選択。却下(自動版)。
- **新しい op 型 `beautify` を独立実装**: `_apply` のロジックが style/resize/align と
  完全に同一になるため、コード重複。既存機構への相乗りを選択。

## 影響 (Consequences)

- データモデル: pen シェイプの `type`/幾何フィールドのみ変更。新規フィールド追加なし。
- Undo/Redo: 複数シェイプの一括 beautify も1回の Ctrl+Z で完全に戻る(`origSel` も復元)。
- ロック済み・pen 以外のシェイプは対象外(既存パターンと同じガード、テストで確認)。
- テスト: `recognizeStroke` を人工的な点列(完全な矩形/楕円/直線 + 意図的なジッター、および
  ランダムなスクリブル)で検証。`doBeautify` は認識・非認識混在の選択、ロック済みシェイプの
  除外、単一 undo/redo を非空虚テストで固定。
