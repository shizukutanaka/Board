# ADR-0849 — 切断コメント残片の第二修復スイープ

## 背景

ADR-0580 / 0807 / 0829 のバイト刈り込みスイープは ~19KB を回収したが、
各行を固定幅で切り詰めた結果、**文の途中でコメントが切断**された残片が多数残った
(行末が `…u` `…th` `…rescanin` `…UNROTAT` のように単語の途中で終わる)。
ADR-0847 (round596) が先頭の5箇所を修復した。本 ADR は残存箇所の第二スイープ。

## 実害

- コメントが false information に見える — 読者が「未完の文」を読んで実装意図を誤読する
- LWW / wire / undo などの**収束不変条件を説明するコメント**ほど長文化していたため、
  切断は最も高リスクな説明に集中していた (clockNewer, _lwwSkip, _mergeSnapshotOp,
  _idIndex, _ptrReset など)

## 手法

1. `grep -nE "// .*( [a-z]{1,2}| [A-Z]|,[a-z]{1,2}|[A-Z]{4,})$"` で短い語尾/
   大文字断片/カンマ語尾で終わるコメント行を全列挙 (~97 候補)
2. 次行を読んで**文法上の折返し** (文が次行へ続く正常な改行) を除外
3. 真の中語切断のみ最小補完 — 意図は前後のコードと ADR 番号から復元
4. 同時に、回復した文の冗長な冗語を整理し、**バイト収支を相殺**するため
   近傍の長大コメントブロック (~26 箇所、5 行以上の段落) を圧縮

## 結果

- ~55 箇所の切断コメントを修復 (修復対象は全て「文が完結しない」真の断片)
- 長コメント 26 ブロックを圧縮し、修復で増えた分を相殺
- raw 556,327B (上限 557,056B に対し ~729B 残)
- 2829 全緑

## 判別基準 (次スイープ用)

- **修復対象**: 行末が単語の途中 (`…reso`, `…distann`, `…UNROTAT`) か、
  次行がコード/別文で文が宙吊り
- **除外**: 行末が `a`/`the`/`of` 等でも次行が `//` で始まり文が続く場合
  (通常の折返し)、完全な文で終わる場合
