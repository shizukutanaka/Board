# ADR-0469 — フラグメント再組立を送信者タグ付け

## 状態

実装済 (v1.7.502)

## 背景

`_fragIn` の `_snapIn`/`_opcIn` スロットは送信者を識別しない単一グローバル集合。2ピアが同時に `snap`/`opc` ストリームを流すと seq 空間が衝突し、`!p[seq]` の重複保護がピアを区別しないため **2ストリームの断片が1つの JSON に継ぎ接ぎ**される → `JSON.parse` 失敗でドロップ。`sync-req` 応答は `_loResp` で1人に限定済み (ADR-0455/0465) だが、BC 上で2ピアが同時に 256KB 超の op (`opc`) を発行する窓は残る。

## 決定

`_fragIn` に `src` 引数 (BC=`msg.peer`、RTC=`'rtc'`) を追加し `sn.src!==src` でストリームを再起動。既存の `n` 不一致再起動 (ADR-0448) と同じ「新ストリーム優先」ルール — 継ぎ接ぎ破損の窓を閉じ、先着ストリームのみ損失 (次の flush で回復)。

## 影響

- 並行 oversized メッセージが交差しても破損 JSON を生成しない — 1ストリーム完走 + 1ストリーム再起動。
- 呼び出し元 (`case 'snap'/'opc'`) で `viaRtc?'rtc':msg.peer` を送る — RTC ピアは合成 id なので定数で十分。
