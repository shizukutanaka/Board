# a11y 監査 (2026-07) — 手法・所見・限界

- Status: 完了 (依存ゼロの静的検証。axe-core/Lighthouse による自動監査は未実施)
- 対象バージョン: v1.7.59
- 関連: CLAUDE.md「100点への距離」a11y 外部監査項目、`docs/audit-2026-06.md`

## 手法(そしてなぜ axe-core を使っていないか)

当初の計画は Playwright + `@axe-core/playwright` を scratchpad に一時インストールし、
実ブラウザで index.html を開いて自動監査する案だった。この案自体をユーザーに問う
`AskUserQuestion` 呼び出しがインフラ側のエラー(ストリーム切断)で2度とも失敗し、
ユーザーの明示的な許可を得られないまま npm install を進めようとしたところ、
自動モードの分類器が「外部パッケージのエージェント自己判断インストール」として
正しくブロックした。これは妥当な安全装置であり、回避を試みず設計を切り替えた。

代わりに、**依存ゼロの静的検証スクリプト**で以下を実施した:

1. Board 自身の CSS カスタムプロパティ(トークン)の値を実際に抜き出し、WCAG の
   相対輝度式でコントラスト比を直接計算(ライブラリ不使用、標準の式を実装)。
   ソースコードの既存コメントが主張する比率("7.5:1 AAA" 等)を鵜呑みにせず、
   実際に計算し直して検証した。
2. インタラクティブ要素(ボタン・ツール・input)の `aria-label`/`title` 存在確認は
   目視 + grep で実施(README のアクセシビリティ節の主張との突き合わせ)。

**これは axe-core の代替にはならない**。axe-core は DOM 構造・ARIA ロールの整合性・
実際にレンダリングされた計算済みスタイル(CSS カスケード後の実値)を検証するが、
本監査はソース中の宣言値を直接読むのみで、カスケード解決や JS 実行後の DOM 状態は
検証していない。今後 npm install の許可が得られれば、この監査を axe-core で置き換え
それ以上のカバレッジを確認すべき(残作業として明記)。

## 所見

### 1. フォーカスリングが WCAG SC 1.4.11(非テキストコントラスト、3:1)を満たしていなかった — 修正済み

`.btn:focus-visible`・`.tool:focus-visible` を含む **7箇所**の `:focus-visible`/`:focus`
ルールすべてが `outline:2px solid var(--brand)` を直接使用していた。`--brand` は
`#00C4CC` で固定(テーマ別上書きなし)。実測コントラスト比:

| ペア | ライトモード紙面 (#FFFFFF) | ダークモード紙面 (#0B1220) |
|---|---|---|
| `--brand` (#00C4CC) | **2.15:1 — FAIL**(3:1未満) | 8.71:1 AAA |

つまりダークモードでは偶然 AAA を満たしていたが、**ライトモードのキーボード
フォーカスリングは既定の背景色に対して視認性基準を満たしていなかった**。
README/CLAUDE.md が「全機能キーボード操作可能」を掲げている以上、フォーカスの
視認性はこの主張の根幹であり、静的解析とはいえ看過できない実害のある所見。

**修正**: 新規テーマ対応トークン `--focus-ring` を導入し、ライトモードでは
`--brand-ink`(#003B40、紙面に対し12.36:1 AAA)、ダークモードでは `--brand`
(紙面に対し8.71:1 AAA)を指すよう theme-aware に切り替えた。7箇所の
`outline:2px solid var(--brand)` をすべて `var(--focus-ring)` に置換。
既存の `:root`/`@media (prefers-color-scheme:dark)`/`:root[data-theme=...]`
という3点セットのテーマ切り替えパターン(他のトークンと同一の慣行)に従っている。

### 2. `--brand-ink` の自己申告コントラスト比が誤っていた — コメントを修正済み

ソースの既存コメント `--brand-ink:#003B40; /* text on brand: 7.5:1 contrast AAA */`
は「brand 地に brand-ink 文字」の組み合わせを指していたが、実測すると **5.75:1
(AA、AAA未達)** だった。この誤りは今回の静的検証で偶然発見されたもので、
「なぜテスト前に信じていた数値が違ったか」の教訓としては、**コメントに書かれた
コントラスト比の主張は一度も自動検証されていなかった**ことに尽きる。今回追加した
`test.mjs` の振る舞いテストは、まさにこの再発を防ぐためのもの(下記参照)。
コメントを実測値に修正した。

### 3. `--ink-3`(補助テキスト)は AA であり AAA ではない — 既存コメント通り、問題なし

`--ink-3:#64748B` on `--paper:#FFFFFF` = 4.76:1(AA)。コード自身のコメントも
「4.7:1 AA」と正しく申告しており、これは実装上の問題ではない。README の
「WCAG AAA カラーコントラスト (テキスト 18:1+)」という表現は主要テキスト
(`--ink`)についてのみ正確で、補助テキストまで含めた包括的な AAA 保証では
ない点に留意(既に「18:1+」と主要テキストを名指ししており、誤解を招く表現
ではないと判断。文言変更は不要)。

### 4. Canvas 描画される選択枠・ハンドルの一部は依然として `--brand` 直書き(未修正)

`drawSelection` 内の選択バウンディングボックス描画(`ctx.strokeStyle=getCSS('--brand')`)
は今回のスコープ外とした。理由: CSS の `:focus-visible` と異なり、canvas 上の
選択枠は描画対象の図形やキャンバス背景など可変の下地に重なるため、「紙面に対する
コントラスト」という単純な計算がそのまま適用できない。一部のハンドル
(回転ノブの暗色リング、line 2073 "dark ring: AAA non-text contrast vs cyan")は
既に `--brand-ink` へ切り替え済みで、この配慮自体は以前の改善パスで部分的に
行われている。残る canvas 描画箇所への同様の配慮は、今回のような静的コントラスト
計算では扱いきれず、実ブラウザでのレンダリング確認(axe-core または目視)が
要る — a11y 監査の次のステップとして残す。

## テスト

- 振る舞いテスト: ソースから `--brand`/`--brand-ink`/両テーマの `--paper` の実際の
  16進値を正規表現で抽出し、WCAG 相対輝度式で直接コントラスト比を計算。
  ライト/ダーク双方が3:1を満たすことを固定。同時に「修正前のペア(brand を紙面に
  直接使う)は3:1未満」であることも固定し、このテストが実際にバグを検出できていた
  ことを保証(非空虚性)。
- presence: `--focus-ring` トークンが3箇所すべてで正しく定義され、生の
  `var(--brand)` を使う `outline` 宣言が0件、`var(--focus-ring)` を使う宣言が
  ちょうど7件であることを固定。

## 残作業(次の一手)

1. **axe-core による本格自動監査**: npm install の許可を得てから、Playwright で
   実際にレンダリングした index.html(初期状態・ヘルプモーダル・Share モーダル・
   コンテキストメニューの最低4状態)に対して `AxeBuilder.analyze()` を実行し、
   本監査ではカバーできない ARIA ロール整合性・DOM構造・実レンダリング後の
   計算済みスタイルを検証する。
2. **canvas 描画される選択枠/コネクタのコントラスト**(上記所見4)を実ブラウザで
   目視確認。
3. **実スクリーンリーダーでの操作確認**(NVDA/VoiceOver 等)— canvas ベースの
   描画アプリという性質上、キャンバス自体の内容(描いた図形)はスクリーンリーダー
   から本質的に不可視であり、これは修正すべき「バグ」ではなく画布アプリの構造的
   限界として文書化する必要がある(誤解を招かないよう README に明記するかどうかは
   別途判断)。
