# ADR-0400: RTC スナップショット送信のチャンク化 (ADR-0383 の欠落分)

## 状態
実装済 (v1.7.437)

## 背景
ADR-0383 で 'snap' チャンクの**受信側**は実装されたが、コミット履歴を確認したところ
**送信側のチャンク化が欠落していた** — `dc.onopen` は依然 `_JS(this._snapshotMsg())`
を丸ごと `dc.send()` していた。RTCDataChannel の SCTP per-message 上限 (~256KB) を
超えるスナップショットは `send()` で例外となり、catch で握り潰して静かに送信失敗
していた (大きな盤面で同期が成立しない実害)。

## 決定
`dc.onopen` の送信を常時 64KB 'snap' チャンク化に統一:

```js
const _sm=_JS(this._snapshotMsg()),_n=_ceil(_sm.length/65536);
for(let _i=0;_i<_n;_i++)this.dc.send(_JS({k:'snap',seq:_i,n:_n,data:_sm.slice(_i*65536,(_i+1)*65536)}))
```

小さい盤面も `_n===1` で同じ 'snap' 経路を通る (ワイヤーフォーマットを一本化し、
「通常は生送信・大きい時だけチャンク」の二経路テスト負担を消す)。受信側は既存の
まま — `data≤96KB`/`n≤384`/結合 24MB 上限で防御済み。

## 断念した代替案
- `<=240KB` は生送信、超過のみチャンク (二経路) — 統一性を優先。
- 384 チャンク超 (24MB+ 盤面) の送信側スキップ+トースト — 受信側の n≤384 拒否が
  既に防御しており、実害としては従来どおり「同期しない」以上に悪化しないため保留。
