# ADR-0783 — _dcQ 送信キューのバイト上限

- 日付: 2026-09-29
- 状態: 実装済み

## Context

`_dcQ` (DataChannel バッファ全開時の退避キュー) の上限は件数 4096 のみ。
各メッセージは ≤256KB (ADR-0438) なので、停滞チャネルで理論上 ~1GB の
文字列がキューに蓄積し得た。実際は op が ~200B と小さいため深刻度は低いが、
件数ではなく**バイト**で縛るべきクラス (ADR-0781/0782 と同じ認識)。

## Decision

キューに `_dcQB` (積算バイト数) を持たせ、32MB で頭打ち:

```js
if(q){if(_ln(q)<4096&&(this._dcQB||0)+_ln(m)<=33554432)_pu(q,m),this._dcQB=(this._dcQB||0)+_ln(m);return}
```

閾値は最大の正当バースト ('snap' 384×64KB ≈ 24MB) を超える 32MB — 正当な
送信は通り、異常キューだけが止まる。カウンタのライフサイクルはキューと一致:
生成時 `_dcQB=_ln(m)`、drain/onclose/room 切替で `0` へ戻す。

## Consequences

- 最悪キュー保持量 ~1GB → 32MB。
- バースト直後に `_dcQB` をリセットする経路は既存 `_dcQ=null` 全サイトに揃えた。
- テストピン2件: バイト上限が件数上限より先に効く・上限超過メッセージは棄却。
