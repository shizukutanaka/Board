# ADR-0581: ドキュメント名の改名を LWW で収束

## 状態
実装済み (v1.7.608)

## 背景
`{k:'name'}` ブロードキャストには時計がなく、受信側は無条件に `_setDocName`
していた。2ピアがほぼ同時に改名すると到着順で最終名が決まるため、ピア間で
名前が不一致のまま残留し得た (図形プロパティは ADR-0002 の wclock LWW で
収束するが、docName は op-log 外の独立経路で仲裁が無かった)。

## 決定
- 改名送信に `ts:nowTs()` (既存の単調タイムスタンプ) を同梱
- 受信側は `msg.ts > _nameTs` のときのみ適用 — 遅到着の古い rename は棄却
- ローカル改名も `_nameTs` を更新するため、自改名直後に古いピアの
  rename が届いても採用しない
- `ts` を持たない旧形式メッセージは受理 (後方互換) — `!0` フォールバック

## 影響
- 同時改名が決定論的に収束 (勝者 = 最大 ts)
- 同一 ms の同時改名は remote 側が棄却される (局所優先の決定的タイブレーク)
- snapshot 経由の初期名採用は従来通り (fresh joiner 経路)
