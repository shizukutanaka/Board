# ADR-0431: 上限超過 op のチャンク送信 (`opc`)

## 状態
実装済 (v1.7.466)

## 背景
WebRTC DataChannel の SCTP メッセージ上限 (~256KB) を超える op は
`dc.send` が投げ、既存の `catch(_){}` が呑んでいた — 巨大なペン
ストローク (RDP 後でも数万点) や大きな `addMany` ペーストの op が
**静寂に消失**し、ピア間で発散しうる経路だった。
snapshot (`snap`) と画像 (`img`) には既にチャンク経路があったが、
通常 op には無かった。

## 決定
- 送信側: `broadcast()` でシリアライズ後の op メッセージが 200KB を
  超える場合のみ、`snap` と同一の 64KB フラグメント (`{k:'opc',seq,n,data}`)
  に分割して送信。200KB 以下の op は従来通り単発送信 (事実上全 op)。
- 受信側: `snap`/`opc` を共有の `_fragIn` 単一アセンブリで再結合し、
  従来と同じ後処理 (`_onRecv` 再帰、24MB 上限) に流す。
- 切断時は `_snapIn` と同じ場所で `_opcIn` も破棄。
- 共有化に伴い、送信側も `_fragSend(buf,k)` に集約 (snapshot 送信も同関数)。

## 影響
- 大きな op の静寂消失を解消 — 発散ではなく正しく届く。
- BroadcastChannel 経路は structured clone のため対象外 (従来通り)。
- ローカル動作・既存プロトコルとの後方互換: 旧ピアは 'opc' を無視するのみ
  (巨大 op を受け取れない点は従来と同じ)。
