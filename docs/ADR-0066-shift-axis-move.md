# ADR-0066: Shift+ドラッグ移動の軸拘束

## 状態

採用 (v1.7.124)

## 背景

- 移動ドラッグは自由2軸 — 水平・垂直に正確に動かすには目視 or ナッジ要。
- draw.io / Figma / PowerPoint の標準: **Shift+ドラッグで移動を支配軸に拘束**
  (水平 or 垂直)。Board の Shift はリサイズ比率保持・回転15°スナップ等
  「拘束」の修飾子として既に一貫した意味を持つ — 移動だけが未対応。

## 決定

- `moveDelta(wp,shift)`: `shift` 真のとき支配軸に拘束
  (`|dx|>=|dy| → dy=0`, 逆は `dx=0`)。グリッドスナップ適用後の値に対して
  ゼロ化 — グリッド整列と両立。
- Shift 拘束中は objectSnap (エッジ/中心吸着) をスキップし guides も出さない
  — 拘束と別系統の吸着が競合するため (Figma と同じ判断)。
- シグネチャ変更は `moveDelta(wp)` → `moveDelta(wp,shift)` — pointermove
  (`doMove`) と pointerup (`endSelect`) の両経路で `e.shiftKey` を渡す。
## 断念した代替案

- **45° 斜め拘束も含める** (Figma 方式): 3方向の判定コストと「斜め45°が
  欲しい」実用度を勘案し、水平/垂直のみに限定 — 実装1行。
- **拘束方向をドラッグ開始時に固定**: 途中で支配軸が変わると切り替わる
  仕様にした (Figma 同様) — 固定だと意図しない軸に吸着し続ける。
- **ナッジでの代替**: 既に可能だが大きな移動は非効率。

## 影響

- Shift+ドラッグで水平/垂直移動。`doMove`/`endSelect`/`moveDelta` の
  3点のみ。undo (`move` op の dx/dy は拘束後の値)・同期は既存経路。
- readout が `+N, 0` / `0, +N` を表示するため拘束状態は常に可視。
