# ADR-0059: スタイルパネルを選択図形に同期する

## 状態

採用 (v1.7.117)

## 背景

`docs/audit-2026-06.md` 第1弾 §8 の残課題「選択時にスタイルパネルが
対象図形の値を反映しない(全コントロール共通の既存制約)」。ストローク/
フィル/破線/サイズ/不透明度の各コントロールは常に `state.style`
(グローバル既定) を表示し続け、選択した図形の実際のスタイルは一切
反映されなかった — Excalidraw/figma/drawio はいずれも選択のスタイルを
インスペクタに表示するので、これは UX のギャップ (選択図形の色を変えた
つもりがグローバル既定に残り、次の新規図形に漏洩する事故の温床)。

## 決定

`frame()` で選択署名 (`size+'|'+[...selection].sort().join(',')`) を検出し、
変化時のみ `_syncStylePanel()` を実行:

- 各プロパティ (stroke/fill/dash/size/opacity) について、選択中の
  **ロックされていない** 図形すべてが同じ値を持つときのみ採用 —
  混在値のプロパティはパネルを触らない (per-property 判定なので
  「色だけ混在・サイズ共通」ならサイズ欄だけ更新される)。
- 採用した値は `state.style[prop]` と対応するコントロール
  (swatch `aria-pressed`、`input.cp`、スライダ + `sizeVal`/`opacVal`)
  の両方に書き込む → 手でスウォッチを変えた後で選択を変えても
  「最後に触った色が幽霊として残る」漏洩が消える。
- `null` は fill のみ意味あり (フィルなし)。stroke/size/opacity/dash の
  null/undefined (group 等のスタイル無し図形) は採用しない。
- 空選択では何もしない — パネルは最後の状態を保持する (どのアプリも同じ)。

frame() 内で署名比較する設計は ADR-0011 `Net.sendSelectionIfChanged`
と同じ理由: `state.selection` は 39 箇所で直接 mutate されるため
setter 経由にできず、RAF 境界での差分検出が唯一の汎用フック。署名計算は
選択ソート済み join で、実用上の選択サイズ (<数百) では ~50μs 以下。

## 断念した代替案

- **最初の図形の値を常に採用**: 混在選択で誤った値を表示するため却下
  (Excalidraw も uniform のみ表示に近い)。
- **選択変更を返す setter を導入**: 39 箇所の書換はリスク大。
- **mixed prop に混在インジケータ**: DOM 構造が単一値前提のため大掛かり
  — 据置の方が誤表示より誠実。

## 影響

- 図形を選ぶとパネルがそのスタイルを表示 → 「この図形の色は何か」を
  パネルから読み取れる。スタイル変更のフィードバックループが閉じる。
- 副作用: 選択を変更すると `state.style` も上書きされる — 次の新規図形は
  選択図形のスタイルを継承する (Excalidraw と同じ挙動、直感的)。
