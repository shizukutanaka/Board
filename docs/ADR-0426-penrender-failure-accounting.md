# ADR-0426: `_penRender` 失敗時の px 会計と再試行制御

## 状態
実装済 (v1.7.461)

## 背景
`_penRender` がサイズ超過 (`w*h > PEN_CACHE_MAX_PX` 等) で `null` を返す際、
旧 `e.px` を `_penCachePx` から減算せず `e.R` も更新しなかった。結果:

1. ドロップした bitmap 分の px が `_penCachePx` に残り続け、キャッシュの
   実効容量が恒久的に縮小 (他の生存ペンの早期 eviction)。
2. `e.R` が旧値のまま → 呼出し側のズームバケット条件 (`R>e.R*1.5`) が
   成立し続け、高解像度で必ず失敗する再ラスタライズを**毎フレーム**試行。

## 決定
失敗経路で `_penCachePx-=e.px; e.px=0; e.R=R` を記録してから `null` を返す —
失敗した解像度を記録し、そのバケットでの再試行を止める。ズームが戻れば
`R<e.R/1.5` で正常に再試行される。

## 影響
- キャッシュ会計のリーク解消 + 失敗時のフレーム毎再試行 churn の解消。
- 成功経路・呼出し側の `false` 記録ロジックは不変。
