# ADR-0029: 下書きペンの増分インクスタンプ (committed-segment bitmap)

## 状態
実装済み (v1.7.87)

## 背景
ペン入力中、下書きストロークはポインタイベントごとに **ベクトル全点を再ストローク**
していた。`drawPen` は stroke 毎に `penWidths`(全点の幅配列 O(n))を計算し、
n 個の quadraticCurveTo を毎フレーム走る。ポイントが増えるほど線形に重くなり、
長いストローク(数千点)では筆記中のフレームコストが支配的になる。

これは主要ホワイトボードが共通して解いている問題:
- **Excalidraw** は freedraw 要素をジェスチャ終了まで offscreen へ逐次スタンプし、
  フレームでは「確定済みビットマップの blit + 末尾数セグメントのみ描画」する。
- **tldraw / Perfect Freehand** 系も「入力中は確定済み部分をビットマップ化し、
  新規セグメントのみ追記する」インクリメンタルインキングが定石。

## 決定
`drawPenMaybeCached` が draft を `drawPenDraft` に振り分け、
ストロークを「確定セグメント(ビットマップ)+ 生きている末尾(ベクトル)」に分割する。

### コミット境界
セグメント i は `w[i]`,`w[i+1]` が確定した時点でのみ焼き付け可能:
- `w[i]` は `raw[i±1]` の3点平滑 → `raw[i+2]` が必要
- velocity モードの `raw[i]` は `pts[i±1]` の距離が必要 → `raw[i+2]` 確定には
  `pts[i+3]` が必要 → **i ≤ n-4** でのみコミット (`while(d.c<n-4)`)
- 生きている末尾 (n-3..n-2 の quad + 最終 lineTo) は毎フレームベクトル描画 —
  幅が揺れ続ける部分は常に最新値で描かれるため見た目の劣化ゼロ

### 圧力モードの全体依存
`penWidths` の圧力経路はグローバル極値 `mn/mx` でゲートされ、極値が伸びると
全幅が変わり得る (モードフリップ含む)。`extGrew`/`usePr` 反転を検出したら
ビットマップごと `_inkRebuild` — 通常はストローク序盤の数回のみ。

### ビットマップ成長
ストロークが確保済み矩形を出たら `_inkGrow` が新キャンバスへ旧ビットマップを
`drawImage` 移植して拡張 (初回 pad=(size*2+64)wu で大部分の成長を吸収)。

### ピクセル一致
確定部分を cv に R=zoom*DPR でラスタライズし、**ラスタ原点を現在の
デバイスグリッドへスナップ**した上で、描画時は `setTransform(1,0,0,1,0,0)` +
整数オフセットの **1:1 blit**。これによりブラーはリサンプリングを通さず、
ベクトル版と AA レベルで一致する (実測 diff=2px/600点ストローク)。
R≠zoom*DPR (極端ズーム) 時のみワールド座標 blit にフォールバック。

`d.R` が 1.5× ズームバケットを跨いだら再ラスタ (ADR-0018 と同じバケット規則)。

## 計測
- n=2000 ストロークの追記フレーム: **~0ms** (blit+末尾) vs ベクトル再ストローク
  **0.2ms** — 点が増えるほど差は拡大 (O(1) vs O(n))
- 600点ストロークのスタンプ版 vs ベクトル版ピクセル差分: **2px** (AA ノイズのみ)

## 非目標
- 確定済みペン (非draft) は従来どおり `_penCache` (ADR-0018) — そのまま。
- エクスポート ctx (`c!==ctx`) は従来どおりベクトル — 高品質を保つ。
