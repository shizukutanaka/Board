# ADR-0019 — ペン bbox のメモ化 (O(1) シグネチャ)

- Status: Accepted
- Date: 2026-09-23
- 関連: ADR-0018 (ペンビットマップキャッシュ) — 同じシグネチャ手法を G.bbox に適用

## 問題

`G.bbox` はペンシェイプの包含矩形を毎回**全ポイント走査**で計算する (O(pts))。
呼び出し元はフレーム単位で:
- `inView()` — 可視判定に可視ペン × 1 回
- ミニマップ — 描画対象の**全**ペン × 1 回

実測 (pen 4000 本盤面、全可視ズーム、ADR-0018 適用後): `G.bbox` が
~9,700 コール/フレームで draw() p50 15.6ms の大半を占めていた。

## 決定

`G.bbox` のペン分岐に `_penBboxCache` (id → {シグネチャ + envelope}、
FIFO 8,192 エントリ上限) を追加。シグネチャは ADR-0018 と同じ O(1) 構成:
`pts` 参照 + 長さ + 先頭/中央/末尾点の絶対座標 + size。

- in-place 変異 (translate/flip) は必ず p0/pN を動かす ⇒ 検知
- その他の op は `pts` 配列ごと差し替える ⇒ 参照比較が検知
- 観測上純粋: ヒット時は同一の矩形オブジェクトを返すのみで `state` を変更しない
- ミス時は従来どおり全点走査してエントリを記録 (ADR-0018 とは異なり即時
  記録 — bbox は描画より軽く、ドラッグ中の一時オブジェクトは小さい)

## 却下した案

- **`_penCache` (ビットマップ) のエントリに bbox を同居**: inView は描画経路の
  前段であり、ヒットテスト・export・整列など非描画系にも G.bbox が要る。
  関心事を分けるため独立したキャッシュとした (シグネチャ構成は共通)。
- **`s._bbox` をシェイプにぶら下げる**: shape オブジェクトは clone/serialize/
  op-log 化される対象 — 派生値を混入させない。
- **WeakMap で shape 参照キー**: Store が op 適用時にシェイプを差し替えると
  キーが無効になり miss が増える。id + シグネチャの方が差し替え耐性が高い。

## 検証 (実施済)

- `node test.mjs` 全緑: ヒット時の同一オブジェクト、translate / 末端 / 中点 /
  配列置換の無効化、総当たり包絡との一致を behavioural assert で固定
- 実ブラウザ (pen 4000 + rect 1000、全可視ズーム、25 フレーム):
  **draw() p50 15.6ms → 6.9ms** (ADR-0018 適用前から累計 175 → 6.9ms ≈ 25×)
