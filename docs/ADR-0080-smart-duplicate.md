# ADR-0080: スマート複製 (反復変換 duplicate)

## 状態

実装済み (v1.7.138)。

## 背景

`⌘D` は常に +20,+20 の固定オフセットでしか置かない。Figma/draw.io の
duplicate では「複製→コピーを移動→もう一度 ⌘D」で**移動ベクトルが反復**され、
等間隔の行/列/グリッドが一発で作れる。ボード上でカードやステップ図を
並べる最頻用パターンであり、現状は毎回手で揃えるしかない。

## 決定

- `state.dupIds` (最新 `_placeCopies` で作られた id 集合) と
  `state.dupDelta` (前回の複製オフセット + それ以降にコピー群へ
  コミットされた移動の累積) を追跡。
- `⌘D` 時、選択が `dupIds` のメンバのみで構成されていれば
  `dupDelta` で複製 (反復モード)、それ以外は従来の 20/zoom。
- `_placeCopies` は呼び出しごとに `dupIds`/`dupDelta` をリシード —
  新しい複製チェーンの開始 (doPaste も同じ振る舞いで副作用は無害)。
- move コミット (endSelect ドラッグ + nudgeSelection) で、移動した
  全 id が `dupIds` のメンバなら `dupDelta += (dx,dy)` — ネット変位
  (初期オフセット + 全移動の和) が次の反復ベクトルになる。
- 対象は translate のみ (resize/rotate の反復は現段階で対象外)。

## 断念した代替案

- **コピーの現在位置 − ソースの現在位置を毎回計測**: Figma の厳密な
  仕様だが、ソースが動いた場合の解釈が曖昧になる。配置時ベクトルの
  累積は「ユーザが実際に適用した変換の反復」として素直で、
  実用上ほぼ同じ結果になる。
- **全変換の反復 (resize/rotate/flip も)**: Figma は transform 全般を
  反復するが、複合変換の結合は op 表現をまたぐため複雑。translate の
  みが行列/行の主要ユースケースをカバーする。
- **`dupDelta` を選択変更でクリア**: doDuplicate 呼び出し時の
  `every` 判定で十分 (他物を複製すればリシードされる)。

## 影響

- state に `dupIds`(Set)/`dupDelta`({x,y}|null) を2フィールド追加。
  永続化・同期・undo に関与しない UI 側の補助状態。
- `addMany`/`move` の op 型は無変更 — undo は既存 op で完結。
- テスト: 複製→移動→複製で反復位置を検証 + 未移動チェーンが
  固定オフセットを反復することを検証。
