# ADR-0008 — Share モーダルの役割明示化 + シグナリングコードのコピーボタン

- Status: Accepted (implemented)
- Date: 2026-07-01
- 関連: `docs/feature-triage-2026-07.md` §3(真の過剰候補)、`docs/feature-backlog.md` FT-05

## なぜ (Context)

`docs/feature-triage-2026-07.md` §3 が指摘した通り、Share モーダルの手動 WebRTC
シグナリング UI は機能自体は正当(ADR-0006/0007 と同じ「自分の端末間・信頼できる相手との
私的共有」の延長)だが、**UX が過剰に複雑**だった。実際のマークアップを確認すると、
具体的なギャップは2つ:

1. **役割の視覚的な区別が無い**: 「招待する側」(招待コードを作成→相手に送る→応答コードを
   もらって接続)と「招待された側」(招待コードを受け取る→応答コードを作成→送り返す)の
   2つのフローが、ラベルなしで1つの `<details>` 内に並んでいた。初見のユーザーは自分が
   どちらの手順に従うべきか、テキストを読み込むまで分からない。
2. **コピー導線が無い**: 招待コード(`#rtcOffer`)・応答コード(`#rtcAnswer`)はいずれも
   readonly textarea に出力されるだけで、コピーボタンが無かった。ユーザーは手動で
   textarea 内を全選択してコピーする必要があり、特にタッチ端末では選択操作自体が煩雑。
   さらに `#rtcAnswer` 生成後、「これをコピーして相手に送り返す」という次の一手の指示も
   欠落していた。

## 何を (Decision)

1. **各手順ラベルに役割を明記**: 「誘う側 手順1/2」「招待された側 手順1/2」という
   接頭辞を全ステップラベルに追加。追加の CSS クラスは導入せず、既存の `.share-step`
   スタイルのテキストを書き換えるのみ。
2. **コピーボタンを追加**: `#rtcOffer`(招待コード)・`#rtcAnswer`(応答コード)の
   隣に「コピー」ボタンを追加。既存の `shareCopyBtn`(URL コピー)と同じ
   `copyText()` ヘルパーを再利用し、同じ成功/失敗トースト方式(新規トーストキー
   `shareCodeCopied`/既存 `copyFailed`)に統一。新しい `.share-row`(既存クラス、
   URL入力+コピーボタンの行で既に使われているflexレイアウト)でボタンを並べる。
3. **`#rtcAnswer` 生成後の次の一手を明示**: 新しいステップラベルで「上のコードを
   コピーして相手に送り返す」を明記(旧「手順3」ラベルをこの用途に転用)。
4. **未使用の i18n キー `sharePasteAnswer` を削除**: 調査の過程で、どのマークアップ
   からも参照されていない完全な死蔵キーであることを確認(ja/en とも)。削除。

機能面(WebRTC シグナリング処理そのもの、`Net.wrtcCreateOffer`/`wrtcConsumeAnswer`/
`wrtcAcceptOffer`)は一切変更しない — ADR-0006/0007 で確立した「既存の正当な機能に
最小限の到達性/明確性を足す」パターンを踏襲。

## 代替案 (Alternatives)

- **モーダル全体を作り直す(2カラムレイアウト等)**: 却下。`docs/feature-triage-2026-07.md`
  §3 が求めたのは「簡素化」であり、レイアウト刷新は過剰(サイズ・複雑さの増加に見合わない)。
- **役割ごとに別モーダル/別タブに分割**: 却下。既存の `<details>` による折りたたみと
  `<hr>` による区切りは十分機能しており、テキストラベルの明確化だけで解決する問題に
  構造変更は不要。

## 影響 (Consequences)

- 新規 DOM: `rtcOfferCopyBtn`、`rtcAnswerCopyBtn`(いずれも `.btn`、既存の `.share-row`
  クラスで囲む)。
- 新規 i18n キー(ja/en): `shareCopyCode`、`shareCodeCopied`。
- 削除: 未使用キー `sharePasteAnswer`(ja/en 両方)。
- `Net`/`Store`/op-log には一切影響なし(UI 文言とコピー導線のみの変更)。
- テスト: 新規ボタンの DOM 存在・`copyText` への配線・新トーストキーの存在を
  presence check で固定。
