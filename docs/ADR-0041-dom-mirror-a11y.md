# ADR-0041: 図形の DOM ミラー (SR ナビゲーション)

## 状態
実装済み (v1.7.99)

## 背景
spec.md §14.2 の P1 ギャップ: 「リーダーは個々の図形を木構造として辿れない」。
Board のコンテンツは全て canvas の bitmap であり、スクリーンリーダーには
ツールバーと状態バーしか見えない — 図形の存在自体が SR に不可視だった。

緩和はこれまでも蓄積してきた: Tab/cycleSel での図形単位巡回 + `describeShape`
のアナウンス、`sConn`/`#sr` の aria-live、マーキー結果の SR 通知 (ADR-0037)。
しかしこれらは全て「今何が選択されたか」を伝えるだけで、SR ユーザーが
**盤面に何があるか能動的に一覧・走査する経路**は無かった。

## 決定
視覚的に隠した `#shapeMirror` (region) + `#shapeMirrorList` (`<ul>`) を新設し、
図形ごとに `<li><button>` を生成:

- **一覧性**: 各ボタンのラベルは `インデックス. describeShape(s)` — 「3. 矩形
  “議事メモ” @ 120,80」といった読み上げになる。DOM 順 = z 順 (視覚的積層と
  一致する読み順)。
- **アクション**: ボタンを Enter/クリックすると `_mirrorGo(id)` — その図形を
  単一選択し、`fitToContent` と同じ pad/cap ロジックで中央寄せ+収まるズームに
  変更、`UI.announce` で選択内容を読み上げる。
- **再構築は `_gridVer` 連動のみ**: 全ての図形変更が既に `_invalidateGrid()`
  (スナップ索引・ミニマップ・draw culling と同一の dirty キー) を通るので、
  `frame()` の末尾で `_mirrorVer!==_gridVer` のときだけ DOM を再構築する。
  フレーム毎・ポインタ毎の DOM 更新は一切しない。
- **上限 `MIRROR_MAX=300`**: 巨大ボードでの DOM 肥大を防ぎ、超過時は末尾に
  「N 個は一覧に未掲載」の非ボタン要素を置いて省略を明示する。
- テキストは `textContent` 設定のみ — `innerHTML` を使わない (CLAUDE.md
  「innerHTML にユーザー入力を流さない」規約に準拠。describeShape の出力は
  エスケープ済みでもルールを破らない)。

## 断念した代替案
- **仮想化/差分 DOM** (変更された図形のノードだけ更新) → _gridVer 単位の全
  再構築で十分 (300 ノード未満 ≪1ms)。差分追跡はバグの巣になるだけ。
- **`role="listbox"`/`option`/`aria-activedescendant`** → 選択とミラーを分離
  しているため、ネイティブ `<button>` 列挙が最も素直で予測可能。
- **マーキー領域を `aria-hidden` セマンティクスにマッピング** → canvas の
  bitmap を DOM セマンティクスに写す試みは本質的に近似。一覧+ジャンプの方が
  SR の実用パターン (「見出し一覧→ジャンプ」) に近い。
- **ツールチップ等の視覚フィードバックを付ける** → ミラーは視覚的に隠れて
  いるため不要。選択側のハイライトは既存の drawOverlay が担う。

## 影響
- SR ユーザーは盤面を「図形の一覧」として走査し、Enter で任意の図形へ
  ジャンプできる — spec P1 の主ギャップが解消。
- 非 SR ユーザー・描画経路への影響はゼロ (`<ul>` は 1px×1px overflow:hidden、
  `_gridVer` 不変ならフレームコストは比較1回のみ)。
- 300 超のボードでは一覧が切り捨てられるが、明示的に省略数を表示するので
  「見えないのに在る」状態にはならない。
