# ADR-0438: `_sendDC` に SCTP 上限ドロップガード

## 状態
実装済 (v1.7.473)

## 背景
ADR-0432 のバックプレッシャーキューは `d.send(m)` 例外時に `_dcQ` に
再キューし `onbufferedamountlow` で再送する。これは「バッファが一杯」
という一時的失敗には正しいが、**メッセージ自体が SCTP 単一メッセージ
上限 (~256KiB) を超える場合は永久に送れない** — drain が再送→throw→
再キューを無限に回し、キュー先頭の毒メッセージが後続の全送信を塞ぐ。

通常の op (>200KB) は ADR-0431 が `opc` 64KB チャンク化するが、
`_sendDC` を直接経由するメッセージ (cursor/selection/name 等の
`_bcast` 系、`_fragSend` の各断片自体) にもガードはなかった。

## 決定
`_sendDC` 先頭に `m.length>262144 → return`。送れないメッセージは
キューに入れず即 drop。

## 影響
- 巨大メッセージによるキュー閉塞 (そのピアへの全後続配信停止) を防止。
- 64KB 断片化された通常パスは全て閾値未満で影響なし。
