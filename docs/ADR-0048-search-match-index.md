# ADR-0048: 検索ハイライトのマッチリストキャッシュ

- 日付: 2026-09-23
- 状態: 承認
- 関連: ADR-0047 (グループハロー キャッシュ), ADR-0020 (スナップ索引),
  ADR-0041 (DOM mirror)

## 背景

検索ボックスに文字が入っている間 (`_sq` 非空)、`drawOverlay()` は毎フレーム
全形状の `label|text|type` を `toLowerCase().includes(q)` で再走査する。
検索を開いたままマーキー選択やカーソル移動をすると、overlay リペイントの
たびに O(n) の文字列走査が発生する。

マッチ結果は「形状の検索対象テキスト」と「クエリ」のみで決まる。テキストの
in-place 変異は存在せず (テキスト編集は op 経由 → `_gridVer` 増分)、クエリは
入力イベントで `_sq` に代入される — つまり `{_gridVer, _sq}` が完全な
キャッシュキー。現在マッチの強調 (`_sqNav.idx`) はリストのメンバーシップに
影響しないため、キーに含めず毎フレームのスタイル評価に残す。

## 決定

`_sqMatches()` — `{_gridVer, _sq.toLowerCase()}` が変わらなければ順序付き
マッチ配列を返し、変われば再構築。`drawOverlay` は返却配列を走査して
`_sqNav.idx` 比較のみ行う。ADR-0047 と同一イディオム。

## 断念した代替案

- **id の Set キャッシュ**: 走査順序 (描画順 = マッチ番号順) を保持する必要が
  あるため配列が適切。
- **`_sq` 変更時の手動無効化**: `_sq` 自体をキーに含める方が漏れがない
  (input ハンドラの修正忘れが起き得ない)。

## 影響

- 検索中の overlay リペイントが O(matches) に (was O(n) の文字列走査込み)。
- test.mjs: presence check (`_sqMatches`/`_sqVer`/`_sqQ`) を追加。
