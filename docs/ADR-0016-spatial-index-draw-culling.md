# ADR-0016: 空間索引を描画パスに拡張(ビューポート矩形クエリによる粗選)

- Status: 実装済み (v1.7.75, FT-14)
- Date: 2026-09-23

## 背景 / 問題

`draw()` は毎フレーム `state.shapes` を**全件**走査し、`inView(s,view)` で各シェイプの
bbox を計算してビューポート外を除外していた。`inView` は 1 シェイプあたり `G.bbox()`
呼び出し + 4 比較と安いが、O(n) であること自体が構造上のコストで、
`docs/feature-backlog.md` FT-14 が指摘する通り 2000 図形超の盤面で顕在化する:
描画対象が数十個でも「除外判定のための全件走査」は毎フレーム全コストを払う。

`pickTop` には既に `_buildGrid`/`_queryGrid`(200 単位の均一グリッド、ADR-0009 と同じ
`_invalidateGrid` choke point で無効化)が実装済みだが、用途はポイントクエリ
(ヒットテスト)のみで、描画パスには再利用されていなかった。

## 決定

`_buildGrid` の出力を描画パスにも再利用し、ビューポート矩形でセルクエリする
`_gridRectCandidates(grid, view)` を追加する。

- **粗選 + 精密判定の2段**: グリッドで「ビューポートに触れ得るシェイプ」の候補
  Set を作り、その後 `inView()` が従来通り精密に判定する。グリッドはあくまで
  フィルタで、描画可否の最終決定は `inView` に残る — 視覚結果は変更前と**完全に同一**。
- **大きさで単純化しない**: 線・矢印の端点パディングや `size` ストローク幅で bbox 外に
  はみ出る分を吸収するため、矩形クエリのセル範囲は 1 セル(200 単位)外側に拡げる。
  超過分は `inView` が落とすので偽陽性は無害。
- **グリッド構築は既存と共有**: `_grid` は lazy build + `_invalidateGrid()` で破棄、
  Store の op 適用ごとに無効化される既存の仕組みに乗る。`pickTop` と同じ
  `state.shapes.length>40` の閾値で発動(小盤面では線形走査の方が安い)。
- **bbox を持たないシェイプ**: `_buildGrid` が従来 `continue` で落としていたものを
  `big`(常時候補)へ入れる。実装上 `G.bbox` は全型で非 null を返すが防御的に
  網羅する。`pickTop` 側は `G.hit` が既に偽を返すため影響なし。
- **z 順序の保持**: 候補は `Set` に入れ、`state.shapes` の配列順で
  `has(s)` 判定して描画 — z-order は配列順そのまま。

## 代替案

- **dirty-rect(差分再描画、FT-13)**: 変更領域のみ再描画する本格最適化。効果は大きいが
  レンダーループの再設計が要り高リスク。本変更は「どのシェイプを評価するか」の
  走査コスト削減であり、dirty-rect を将来やる場合もこの粗選は併用できる
  (独立した改善として先に着地)。
- **quadtree**: 均一グリッドで十分(シェイプ密度が極端に偏る盤面以外で差は小さい)。
  既存 `_buildGrid` のデータ構造を変えない範囲に留めた。

## 計測

### マイクロベンチ(走査単体、Node で関数を同一実装で計測)

5000 図形(rect 2/3 + 120点 pen 1/3、10万単位の遠方に分散 = ビューポート外)を
`inView` 線形走査 vs `_gridRectCandidates` で比較(200 回平均):

| | 走査コスト / frame |
|---|---|
| 線形 `inView` 全件 | **2.90 ms** |
| グリッド矩形クエリ | **0.004 ms** (~727×) |
| `_buildGrid`(変異時に1回のみ) | 9.75 ms |

pen ストロークの `G.bbox` は全ポイント走査のため、ペン比率が高い盤面ほど線形走査が
支配的なコストになる — 本変更が FT-14 の狙いどおりの箇所を解消する。

### 実ブラウザ A/B (file:// 上の実 Chrome headless, rAF コールバック計時)

同一 5000-図形シードを読み込み wheel ズームで連続描画させたときの frame() 実時間
(変更前 old.html 対比): mean 4.90ms → 3.75ms。フレーム内にはグリッド背景・
ドラフト/オーバーレイ等の共通コストが残るため、差分として走査分の削減が観測できる
(可視描画なしの領域で ~1.1ms/frame の削減)。

## 検証

- `node test.mjs`: presence チェック(`_gridRectCandidates` 定義、draw() 内の
  閾値ゲート、`big` への no-bbox 収容) + 振る舞い(グリッド候補が view 内
  シェイプを含み遠方シェイプを含まない)。
- 実ブラウザ視覚確認: file:// で描画・選択・ズーム・パンが従来通り。
