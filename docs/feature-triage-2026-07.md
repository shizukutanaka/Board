# 機能過不足トリアージ — ソクラテス式問答 (2026-07)

- Status: 記録 (本文書は判断の記録であり、実装は次フェーズ)
- 対象バージョン: v1.7.54
- 関連: CLAUDE.md「100点への距離」製品判断 (2026-07-01)、`docs/research-improvements.md` §3.9、
  `docs/audit-2026-06.md`、`docs/feature-gap-2026-06.md`

## §1 方法と判定基準

ソクラテス式問答法(機能の存在理由を製品の自己像に照らして問い直す)で全機能を選別した。
判定基準は確定済みの製品判断: **「速い・私的・使い捨ての単独スケッチ (scratchpad)」への適合**。

- 過剰 = scratchpad に無い前提(観客・identity・永続ワークスペース)を持ち込む機能
- 不足 = scratchpad の勝利条件(0秒で使い始める・オフライン等価・どこでも動く)を
  実際には満たせていない箇所

問答に加えて、全機能の**到達経路監査**(どの機能がボタン/メニュー/キーボードの
どれから届くか)を実施した。結論: このプロダクトの問題は「過剰」ではなくほぼ全て
「**不足**」であり、不足は1つのテーマに収束する — **タッチ到達不能性**(§4)。

## §2 過剰と疑われ「残す」と決着した機能

問答で正面から疑い、明示的に「残す」と判定したもの。将来同じ疑いを繰り返さないための記録。

| 機能 | 提示した疑い | 決着 |
|---|---|---|
| プレゼンモード + レーザーポインタ (~2%) | 「誰かに見せる」機能であり、単独スケッチに無い前提(観客)を持ち込んでいるのでは | **残す** — 自分のフレームを見返す・整理する用途は単独作業の延長。観客がいなくても無害 |
| P2P sync 一式 (WebRTC + BroadcastChannel + CRDT clock, ~5.6%) | 「使い捨て」は *消えてもいい* 前提だが、同期は *複数箇所で一致し続けさせる* という真逆の力学では | **残す** — 自分のPC↔スマホ間の私的同期は scratchpad の延長。identity 前提の「ワークスペース的コラボ」とは別物(そちらは対象外、CLAUDE.md 参照) |
| IndexedDB 永久蓄積 (単一 DOC_KEY) | 「使い捨て」を名乗りながら実質は永続ノートでは。起動のたびまっさらの方が自己像に合うのでは | **残す** — 「使い捨て」とは対価(登録・課金・プライバシー)ゼロの気軽さの意味であり、データ寿命の話ではない。自動保存は「作業を失わない」という別の価値。ADR-0004 もこの立場を補強 |

## §3 真の過剰候補 (少数)

1. **手動保存 (⌘S)** — 500ms デバウンスの自動保存 (`Persist.schedule`) と完全に重複する、
   キーボード限定の冗長な安心ボタン。存在を知る手段もヘルプの1行のみ。**削除候補**
   (害が小さいため優先度は最低。消すなら help grid / README / i18n も同時に)。
2. **Share モーダルの手動 WebRTC シグナリング UI** — 機能ではなく **UX が過剰に複雑**。
   Step 1 (offer 生成) → Step 3 (answer 貼付) の列の間に「相手から answer コードを
   もらう」という中間段階の説明・導線が視覚的に欠落しており、初見では完遂困難。
   **簡素化候補** (機能自体は §2 の通り正当)。

過剰はこの2点のみ。v1.7 までの機能群は scratchpad の自己像に対して概ね規律が保たれている
(サイズ予算時代の抑制と、multipage/コラボを見送り続けた判断の効果)。

## §4 不足 — 中核テーマ: タッチ到達不能性

**事実**: コンテキストメニューの唯一のトリガーは `contextmenu` DOM イベントで、
long-press ハンドラは存在しない (`pointerType` 判定は 0 件)。iOS Safari 等は canvas 上の
long-press から `contextmenu` を確実には発火しないため、**タッチ端末では右クリック
メニュー全体が事実上開けない**。README は「完全オフライン」「どこでも動く」を掲げ、
PWA としてホーム画面追加まで案内しているのに、タッチでは以下がすべて使えない:

### 4.1 メニュー限定 (ショートカットすら無い)
- **整列 / 均等配置** (`ctxAlign*`)
- **全消去** (`doClearAll` — トリガーは `ctxClear` のみ。ボタンなし)

### 4.2 メニュー + キーボードのみ (タッチ不可)
- 複製 / コピー / ペースト / 切り取り / 削除 / 全選択
- グループ化・解除、z順序 (前面/背面/一段)、フリップ (⇧H/⇧V)、ロック、
  スタイル転写 (⌥C/⌥V)

### 4.3 キーボード限定 (ボタンもメニューも無し)
- 回転 15° 単位 (`,`/`.`) — ノブドラッグは可能だが固定角はキーボードのみ
- 検索 (⌘F)、グリッド (G)、スナップ (⇧G)、ミニマップ切替 (M)、
  **スケッチ整形 (⌥B, ADR-0005)** ※実装したばかりの機能も同じ轍を踏んでいる
- **SVG 出力 (⌘⇧E) / PDF 出力 (⌘P) / .board 出力 (⌘⇧S)** — 出力ボタンは PNG のみ

### 4.4 その他の不足
- **.board インポートが drag-drop 限定** — `<input type=file>` が存在しない。
  タッチ端末ではバックアップからの復元が不可能
- **ツールバー縦レールのオーバーフロー** — 11 ツールがスクロール不可の固定レールに
  並ぶため、背の低い横持ち画面では下方のツール (frame/eraser) に届かない
- **フレームナビゲーションがプレゼンモード専用** — キャンバス上でフレームへ
  ジャンプする導線が無い (ミニマップの目視パンのみ)

### 4.5 補足: 「全機能キーボード操作可能」の非対称性
README のアクセシビリティ節は「全機能キーボード操作可能」を掲げ、これは達成している。
しかし対称の「全機能タッチ操作可能」は掲げられておらず、実態は上記の通り大きく欠けている。
キーボードユーザーへの配慮(a11y)とタッチユーザーへの配慮は同じ「入力手段の多様性」問題
であり、後者だけが放置されているのが現状。

## §5 修正候補の優先度 (次フェーズへの提案 — 本文書では実装しない)

| 優先度 | 提案 | 効果 / コスト |
|---|---|---|
| **P1** | **long-press (~500ms 静止) でコンテキストメニューを開く** | 一撃で §4.1・§4.2 の全item + 回転・整形の大半がタッチ到達可能になる。最小コスト・最大効果。実装は pointerdown からのタイマー1本 + 移動キャンセル |
| **P2** | .board インポートの**ファイルピッカー** (`<input type=file>`) + **エクスポートのドロップダウン化** (PNG ボタン → PNG/SVG/PDF/.board) | バックアップ復元と全出力形式がタッチで完結。UI 追加は小 |
| **P3** | ツールバーに `overflow-y:auto` (CSS 1行) | 横持ち画面での到達不能を解消 |
| **P4** | ⌘S 削除、Share モーダルの導線整理 (§3) | 過剰の解消。急がない |

P1〜P3 が完了すれば「どこでも動く」の看板とタッチ実態が一致する。逆に P1 を跳ばして
新機能を足すと、⌥B と同様に「キーボード限定の新機能」を量産することになる —
**新機能より先に到達経路を直すべき段階**にある。
