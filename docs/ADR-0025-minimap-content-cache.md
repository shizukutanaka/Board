# ADR-0025: ミニマップのコンテンツビットマップキャッシュ

- ステータス: 採用 (v1.7.83)
- 日付: 2026-09-23

## 背景

`Minimap.draw()` は呼ばれるたびに **全シェイプを縮小レンダリング** し直す —
160×100 のミニマップでも、4000 ペンの盤面では全ペン点の走査が毎フレーム走る。
`Minimap.schedule()` は `invalidate()` から呼ばれるため、**パン/ズーム**
(ビューポート矩形だけが変わる操作) でも全コンテンツを再ラスタライズしていた。

実はミニマップの描画内容は 2 つに分解できる:

1. シェイプ群の縮小描画 — **シェイプデータのみに依存** (`_gridVer` が既にその
   変更シグナル)
2. ビューポート矩形 — 毎回描き直しても 1 本の strokeRect で済む

## 決定

コンテンツ部分を 160×100 のオフスクリーンキャンバスに描いて `_gridVer` で
メモ化。`draw()` は:

```js
if(_sceneVer!==_gridVer)_renderScene(); // シェイプ変更時のみ全走査
mx.drawImage(_scene,0,0);               // O(1) blit
// ビューポート矩形はキャッシュ済みの _sc/_ox/_oy で毎回描画
```

つまりパン/ズーム中のミニマップ更新は `drawImage + strokeRect` のみで、
全シェイプ走査が完全に消える。

## キャッシュ無効化の網羅

`_scene` を腐らせる経路を全て塞ぐ:

- `_gridVer` 変化 (シェイプ追加/変更/削除/ロード) → 自動的に再レンダー
- `applyTheme()` → `Minimap.invalidate()` (配色は CSS 変数経由)
- `img.onload` (`getImg`) → `Minimap.invalidate()` (非同期ロード完了で
  プレースホルダから実画像へ変わる)

## 測定根拠

4000 ペンの盤面でペンを引く/シェイプを動かすと、ミニマップがフレームごとに
全点を再走査していた。キャッシュ後、同一 `_gridVer` 内の再描画 (パン/ズーム、
ビューポート移動) は定数時間になる。実測値は CHANGELOG に記載。

## 却下した代替案

- ミニマップをシーンキャンバスから `drawImage` 縮小コピー — シーン描画範囲が
  ビューポート限なので全体像を得られない
- 描画を worker へ — 単一ファイル・デバッグ性とのトレードオフ (ADR-0024 と同じ)
