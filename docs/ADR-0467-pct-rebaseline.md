# ADR-0467 — ルーム切替で `_pCt` を再ベースライン化

## 状態

実装済 (v1.7.500)

## 背景

ADR-0463 の `_pCt` (SR announce のピア数デルタ追跡) は、`_pr()` クリア (ADR-0458) と同じ行で再ベースライン化されていなかった。旧ルームのカウントが残ると:

- 旧 3 → 新ルーム空 (0) → 次の `_onConnChange` で `n=0 < _pCt=3` → 「3人退出」の phantom announce (実際はルーム切替による一括クリア)
- 旧 0 → 新ルームに既存ピア → 最初の変化が過去との差分で誤差を含む

実害は announce 文の回数ズレのみ (新ルームの最初の join/leave が正しい件数で鳴らない) だが、ADR-0464/0466 と同根の room-scoped 状態残存。

## 決定

`_pr()` クリア直後に `this._pCt=_pr().size` で再ベースライン化 (RTC ピア分は継続カウント — 彼らは残留するためデルタ基準点として正しい)。

## 影響

- 新ルームでの最初の join/leave announce が正しい件数差分で発火 — 旧ルームのゴーストが SR ログに出ない。
