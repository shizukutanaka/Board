# ADR-0851 — 切断コメント残片の第三修復スイープ

## 状態

採用 — v1.7.877 で実施済み。

## 背景

ADR-0580 (~17.9KB)・ADR-0807 (~870B)・ADR-0829 (~1.3KB)・ADR-0849 (~55箇所) の
連続するバイト刈り込みは、コメント行を固定バイト予算で切断したため、単語途中で
止まったスタブ (`thi`, `selecte`, `BroadcastChann`, `loc`, `audi`, `scr` 等) と、
被修飾語を失ったぶら下がり節 (`merge them`, `since`, `callers`, `the fra`) を
コードベース内に残していた。

ADR-0849 は「`{1,2}` 文字で終わるコメント行」のシグネチャで第二スイープを行ったが、
3 文字以上の中語切れと、小文字始まりの「頭なし節」(前の行で文が終わっているのに
節だけが残った行) は拾えなかった。

## 検出ヒューリスティック (第三世代)

1. **中語切れ尾部**: `//` 行が `[A-Za-z]{2,10}` で終わり、次の非空行が
   (a) 大文字始まりのコメント、または (b) コード — 単語途中での切断を示す。
2. **頭なし節**: `//` 行が小文字始まりで、直前の非空行が非コメント、または
   終端記号 (`.`, `)`, `:`, `。`) で終わる — 先行文から剥がれた節を示す。

両ヒューリスティックで ~400 候補が浮かぶが ~95% は文法上正しい折返し
(例: `…contents. A` + `frame nested inside`)。真のヒットは「単語の途中で
止まっている」ものだけ — 各サイトを読んで確認し、意図を再構成して修復した。

## 実施内容

- ~80 箇所の切断コメント残片を文法修復 (LWW/wire/undo/presence/import/RTC の
  収束・安全側コメントを含む — 例: connEnds の del 経路、_snapshotMsg の
  SHAPE-ID キー根拠、_fragIn 送信者タグ、_imgSent バイト上限、wake lock、
  html lang 同期、BroadcastChannel/RTC 住み分け、_lwwSkip 逆適用ガード)
- 修復による増分 (~1.4KB) は長大コメント 10 ブロック (PEN BITMAP CACHE /
  DRAFT INK STAMP / OVERLAY LAYER / nowTs / _lwwSkip-undo / byId index /
  validPatch / remoteDel / DPR watch / Security-dataUrl) を圧縮して相殺 —
  raw 557,053B で RAW_CEILING (557,056B) 内を維持。

## 規約

- コメント修復は「文法を回復する最小補完」に留める — 意味の書き換えはしない。
- 圧縮は情報量を失わない範囲 (冗長副詞・括弧内言い換えの畳み込み) に限る。
- バイト刈り込みを今後行う際は単語境界で切る — 中語切れは禁止 (ADR-0580 系譜の反省)。
