# ADR-0647: ページ別プレゼンス (page-scoped peer presence)

## 状況
ADR-0646 で多ページを導入した直後の不整合: ピアのカーソルは `{x,y}` だけを
持ち、「どのページに居るか」を表現できない。ページ 2 のピアがページ 1 を
見ている相手の画面にカーソルとして描かれる — 座標は共有キャンバス上の
実座標だが、見ている盤面が違うので誤導になる。ピア選択輪郭は
`drawPeerSelections` が図形の `_pgOk` を通るため自動的にページ連動済み。
残る穴は shape 非束縛のカーソルのみ。

## 決定
プレゼンスメッセージに送り手のページを同梱する。

- `cursor` (`{x,y}` および `h:1` hide) と `selection` メッセージが
  `pg: state.curPg` を乗せる。単一ページ盤面では `curPg===null` のため
  `pg:null` — フィールドは常に存在し、旧受信側は無視する (後方互換)。
- 受信側は `p.pg = (string ? ≤64 文字で truncate : null)` と記録。
  `selection` でも更新するので、カーソルを動かさずページだけ切替えた
  ピアの `pg` も追随する。
- `drawPeerCursors` は `_pgOn() && p.pg && p.pg!==state.curPg` のピアを
  skip。**`p.pg` が無い/ null のピアは常に描く** — 旧バージョンのピアは
  全図形を見ている (フィルタを持たない) ため、そのカーソルはどのページ
  から見ても実座標として有意。
- `switchPage` は `Net.sendCursorHide()` で自分のカーソルを一度消す —
  移動前のページ座標がピアの画面に残らない。次の pointermove が新しい
  `pg` で再送信する (60ms スロットルは hide 経路でリセット済み)。

## 非目標
「ピアが何ページに居るか」の UI 表示 (ピア一覧バッジ等)・ページ追従
(follow-the-presenter) は後続。presence の `pg` は描画フィルタ専用で、
ピア側の強制ページ遷移は起こさない (curPg はローカルビューフィルタのまま)。

## 検証
`test.mjs` +1 ピン +3 実動作: cursor/selection メッセージの `pg` 記録、
`selection` での `pg` 更新、未同梱 (旧ピア) で `p.pg` がクリアされ
全ページ可視に戻ること。
