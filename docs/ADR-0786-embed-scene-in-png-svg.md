# ADR-0786 — 書き出し画像へのシーン埋め込み (Embed scene)

- Status: Accepted (implemented)
- Date: 2026-11-18
- 関連: 競合優位性調査 (2026-11-18) の機会1、Excalidraw の Embed scene、ADR-0114 (選択の .board 書き出し)、ADR-0043 (content beats extension)

## なぜ (Context)

Board の弱点として README 自身が明記していたのが「SVG を読み戻すと構造が
元どおりに戻らない」ことであり、PNG は再編集できない画像でしかなかった。
一方 Excalidraw は PNG/SVG 書き出し時にシーン全体を画像ファイル内へ埋め込み
(Embed scene)、「画像がプレビュー兼ソース」になる仕組みを実証しており、
周辺生態系 (Obsidian 連携等) の土台になっている。

Board にとってこれは「メールやチャットで画像を送る = 編集可能なボードを
送る」になる変更であり、書き出し・読み込みの局所変更で収まる。

## 決定 (Decision)

書き出し時に `.board` と同一のシーン JSON (`sceneJSON` — 従来 exportBoard が
組み立てていたペイロードそのもの) を画像へ埋め込む。

- PNG: IHDR 直後に tEXt チャンク (キーワード `board-scene`) を挿入する。
  tEXt は Latin-1 のため、値は UTF-8 バイト列の base64 とする。CRC-32 は
  遅延構築テーブルで自前計算する (新規依存なし)。対象は `_renderPngBlob`
  経由の書き出し (全体/選択の PNG 保存とクリップボードコピー)。
  ビューポート切り出し (exportViewportPNG) は「見えている範囲の写真」と
  いう意味論が異なるため対象外とする。
- SVG: `buildSVG` の第3引数 `scene` を渡すと、`<metadata data-board-scene="1">`
  要素へエスケープ済み JSON を埋め込む。書き出しとクリップボードコピーの
  両方が対象。

読み込み時は埋め込みを先に検査する。

- ファイルピッカー (.png を受け付けに追加) / ドロップ / SVG ファイルの
  貼り付けで、埋め込みがあれば `_restoreScene` が `.board` の全体入れ替え
  経路 (importBoard を Blob 経由で再利用) でボードとして復元する。
  バックアップ・Undo・ページ採用の意味論は .board ファイルを開く場合と
  完全に同一になる。
- 埋め込みが無い画像は従来どおり画像として取り込む (後方互換)。
- 埋め込みが存在するが復号・解釈できない場合は、通常の画像としても開かず、
  `invalidBoard` のエラーを表示して失敗する。黙って壊れたボードや、
  意図しない画像差し替えは起こさない。PNG 抽出 (`_pngScene`) は
  「無し = null / 壊れている = false」を区別して返す。
- ラスター画像の貼り付け (クリップボード) は従来どおり画像挿入のままとする。
  復元の入口は「開く / ドロップ」に限る (コピー元のボードが残る経路で
  全体入れ替えを起こさないため)。

## 検証

- 純関数の往復をテストで固定: CRC-32 の標準チェックベクトル、PNG への
  埋め込み→抽出がバイト単位で一致 (日本語・マークアップ文字を含む)、
  チャンク CRC の独立実装による再計算照合、壊れた base64 での false 返却、
  SVG メタデータのエスケープ往復 (`</metadata>` を含む文字列でも壊れない)。
- ドロップ経路の実走テスト: 埋め込み PNG / SVG をドロップするとボードが
  シーンへ入れ替わり、壊れた埋め込み PNG はボードを変えずエラー表示になる。
- `node test.mjs`: 2840 pass / 0 fail (従来 2816 + 新規 24)。
  PNG 書き出しの完了が非同期になったため、exportSelection の既存テストは
  各 PNG 書き出しの完了を待つ形に合わせた (期待する toast 順序は不変)。
- index.html の raw サイズ上限 (暴走ガード) は本機能の ~5KB 分を
  547KB → 552KB へ引き上げた (ADR-0785 の前例と同型)。
