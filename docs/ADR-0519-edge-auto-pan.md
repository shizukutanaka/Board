# ADR-0519: ドラッグ中のエッジオートパン

## 状態

実装済み

## 背景

Board のキャンバスは無限平面だが、ドラッグジェスチャ (移動/リサイズ/マーキー/
描画/waypoint/ebend/cbend/lblpos) は**可視領域の端で止まる** — ポインタが
画面端に達しても viewport は動かず、「端の向こうに置きたい」はドラッグを
一度切って pan → 再ドラッグの往復が必要だった。Figma/draw.io/tldraw/Miro
全てがエッジオートパン (drag-to-edge で連続スクロール) を実装しており、
欠如は明確な UX ギャップ。

## 決定

`_PM` ハンドラ末尾で `_edgePanKick()` を呼び、ポインタが端 24px 内なら
rAF ループ `_edgePanTick` を起動:

- 速度は侵入深さに比例 (`S*(depth)/M`、最大 14px/frame)
- `_pointers.size>=2` (ピンチ中) と `ptr.panning` (hand/中クリック pan 自身)
  は除外 — pan ジェスチャを更に pan しない
- ポインタが静止していても pan 継続 (イベント駆動ではなく rAF)。ループは
  `ptr.down` が落ちると自然終了
- 各ドラッグ種は次の `_PM` で `wp=_s2(sp)` を**成長した viewport から再導出**
  するため、追加のアンカー補正なしに全種が正しく延長される

既知の簡略化: 完全に静止したポインタでは shape はワールド固定のまま viewport
だけが pan する (Figma の「カーソルに吸着して進み続ける」挙動ではない)。
次の本物の pointermove で差分が一括反映されるため実害は小さい。

## 影響

- 画面端へのドラッグで視界外へ配置/選択/描画が可能に
- 併せて `_s2({x:e.offsetX,y:e.offsetY})` (7サイト) を `_o2w(e)` に集約、
  本機能の追加分を相殺して raw を 524,182B (<524,288) に収めた
- test.mjs 2078 全緑 (ピン1件追加)
