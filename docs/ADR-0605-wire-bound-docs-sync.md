# ADR-0605: ワイヤ境界・ジェスチャライフサイクルの文書同期

## 状態
実装済 (v1.7.632) — docs のみ

## 背景
ADR-0602 (op 配列上限の盤面上限化)、ADR-0603 (受理不能フラグメント
ストリームの両端ガード)、ADR-0604 (hidden/pagehide のジェスチャ取消)
がコード側の不変条件を変更したが、architecture.md は旧境界を記述した
ままだった:

- frag 再構成の「24MB 上限」のみで、宣言 n>384 の明示棄却と
  送信側 `syncTooLarge` 中止が未記載 — 読み手が受信側だけの
  ガードと誤認し得た
- wire キャップ節が zorder/group の ≤600/≤64 に留まり、
  `MAX_OP_SHAPES=SHARE_MAX_SHAPES` への統一と「実効の DoS 上限は
  ワイヤサイズ (256KiB / 24MB) にある」という設計判断が未記載
- ジェスチャライフサイクル節が pointercancel/lostpointercapture までで
  hidden/pagehide の取消経路が未記載

## 決定
- `snap`/`opc` 断片の説明に n>384 両端ガード (送信中止 + 受信棄却)
  を追記し「送ったが届かない」分岐排除を明記
- wire キャップ節に「op 配列上限 = 盤面上限」規則を新設 —
  op 数ではなくワイヤサイズが実効の DoS 上限という不変条件を固定
- Input 節のキャンセル経路列挙に visibilitychange→hidden /
  pagehide を追加

## 影響
- 文書とコードの不変条件が一致 — 次の監査者が「配列 500 固定」を
  前提に追加ガードを書く事故を防ぐ
- ジェスチャキャンセル経路の全列挙が正確に
