# ADR-0034: ペンコミット時 RDP — 反復インデックス実装 + ズーム適応 eps

## 状態
実装済み (v1.7.92)

## 背景
`endPen` は採点したストロークを `_rdp(pts,0.5)` で Ramer–Douglas–Peucker
簡略化してからコミットする。2 つの問題があった:

- **固定 eps=0.5 (world 単位)**: `contPen` の採点分解能は `1/viewport.zoom`
  ワールド単位 — ズームインして描くほど細かい点を記録する設計。一方コミット時の
  RDP は常に 0.5wu を捨てるため、**ズームインで描いた精密な筆跡がコミットで
  失われていた** (採点した分解能を簡略化が上回って捨てる不整合)。
- **再帰 `pts.slice()`**: 各分割で配列を物理コピー — n=2000 のストロークで
  O(n log n) の割当 + GC 圧が乗る。コミット時のみだが連続書きの発火点は多い。

## 決定
- **`eps = 0.5 / state.viewport.zoom`**: 簡略化許容値を採点分解能に比例させる
  (分解能の半分)。zoom=1 で従来の 0.5 と一致 (回帰なし)、zoom=4 なら 0.125
  で精密筆跡を保持、ズームアウトでは入力自体が粗いため結果はほぼ不変。
  「保存される品質がズームに依存する」点は `contPen` の採点が既に同じ性質を
  持つため製品として一貫。
- **反復インデックス版**: `Uint8Array` の keep マスク + `[lo,hi)` レンジを
  スタックで走査 → 配列コピーなし、出力は厳密に同一 (テストで再帰参照実装と
  21ストローク×4eps の完全一致を検証)。

## 断念した代替案
- eps 固定のまま `1/zoom` に揃えない理由 — 従来値 0.5 を越える粗化は不可
  (zoom>1 で品質低下)、ズーム比例が自然。
- Visvalingam-Whyatt (面積基準) — RDP と同量の実装複雑さで既存結果との
  差分が出るため、挙動不変の反復化を優先。

## 影響
ズームイン精密作 (手書き文字・細部スケッチ) のコミット品質が向上。
長ストロークのコミット時割当が減少。
