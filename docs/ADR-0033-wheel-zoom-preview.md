# ADR-0033: ctrl+wheel ズームのスナップショットプレビュー

## 状態
実装済み (v1.7.91)

## 背景
ADR-0030 でマルチタッチのピンチズームにスナップショット・スケールプレビューを
導入したが、**デスクトップ側の同等ジェスチャが抜けていた**: トラックパッドの
2本指ピンチは Chrome/Edge/Safari で `wheel` + `ctrlKey` として届き
(MDN: pinch-zoom gestures on trackpads), マウスホイールの ctrl+ズームも同じ
経路に乗る。このバーストは 60-120Hz で連続発火し、毎イベント `zoomAt` →
シーン全再描画が走っていた — タッチピンチで解消したのと同じ「連続ジェスチャ中の
全面再描画」が残っていた。

## 決定
- ctrl/meta+wheel のズーム分岐で、バースト先頭に `_pinchSnapNow()` — ADR-0030 の
  プリスティン canvas スナップショット機構を**そのまま共有** (draw() の
  プレビュー分岐は viewport 差分で正しく写すため wheel 由来でも同一式が成立)。
- スナップショット保持は 180ms のクワイエットタイマー — 最後のズームイベント
  から 180ms 経過で `_pinchSnap/_pinchVp` を破棄して `invalidate()` →
  通常フレームが高精細へ置き換える (地図アプリの blurry→crisp settle と同型)。
- 通常ホイール (ctrl なし = パン) は一切触らない。
- `_resetPinch` (pointerup/cancel で _pointers<2) は従来どおり — wheel バースト中に
  ポインタイベントが来ればスナップショットを破棄して全面再描画 (安全側に倒す)。

## 断念した代替案
- wheel イベントを指ピンチと同一ジェスチャ扱いで `_pointers` に流す —
  ポインタの無い擬似ジェスチャは既存の 2 本指前提と衝突する。
- 各 wheel ステップで旧フレームを自己 drawImage — ブラーが累積する
  (ADR-0030 で棄却済みの理由と同じ)。

## 影響
トラックパッド・ピンチ中のシーン再走査がゼロになり、フレームは
オフスクリーン blit 1 回のみ。settle 後のフレームは直接描画とピクセル一致
(実ブラウザ検証: burst→preview 分岐、180ms settle 後 diff=0)。
