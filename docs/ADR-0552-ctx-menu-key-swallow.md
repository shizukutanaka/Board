# ADR-0552: ctx メニューの未処理キーを呑み込む (バブルしない)

## 状態
実装済 (v1.7.580)

## 背景
ADR-0541 は「ctx メニュー表示中の未処理キーでメニューを閉じる」とし、イベントを canvas
ショートカットへバブルさせていた (「stale なメニュー背後で 'v'/⌘Z/Delete が発火する」のを
避けるため)。実ブラウザ検証でこのバブルにより **Backspace がメニュー越しに選択図形を
削除**することが判明 — メニューが視覚的に開いたまま keydown が canvas まで届く挙動は
ネイティブのモーダルメニューと異なり、ユーザーの「今はメニューモード」の期待を裏切る。

## 決定
`_ctxMenuKeyNav` の else 分岐で `_pd(e); e.stopPropagation(); UI.closeCtxMenu()` とし、
未処理キーはメニューを閉じた上で呑み込む。ネイティブコンテキストメニューの挙動と一致
(開いたメニュー内では menu item 化されたキー以外は無効)。ユーザーがそのキーを canvas に
効かせたい場合はメニューが閉じた後にもう一度押す — 摩擦はゼロではないが、誤削除より安い。

Space/Enter は従来通りネイティブ (focus 中の item activation、ARIA APG)。

## 影響
- 'v'/Delete/⌘Z 等がメニュー表示中に canvas へ届かなくなる
- 誤操作経路 (メニューが開いているのにショートカットが走る) を閉塞
- テスト: 'v'/'Delete' が closeCtxMenu + stopPropagation を両方発火することを pin
