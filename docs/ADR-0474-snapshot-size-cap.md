# ADR-0474: スナップショット取込キャップを全盤面サイズへ

## 状態

実装済 (v1.7.507)

## 背景

v1.7.48 で導入した `MAX_OP_SHAPES=500` は「1 op が運ぶ図形数」の DoS ガードとして設計された
(`addMany`/`clear` の payload)。しかしスナップショット経路がこれを流用していた:

1. `_applySnapshot` (空盤面): `shapes.slice(0,MAX_OP_SHAPES)` → `state.shapes` へ**置換**。
   500 を超える盤面で join すると末尾の図形が新規ピアから**完全に消える**。
2. `msg.ops` merge (非空盤面): `ops.slice(0,MAX_OP_SHAPES)` → 500 超の add op が merge されず
   欠落図形のまま収束してしまう。

スナップショットは「盤面全体」という異なる性質の payload であり、per-op の 500 キャップは
正当な用途を壊していた。外縁は既に「join した断片化ペイロード ≤24MB」で制限されているため、
悪性 payload の曝露は変わらない。

## 決定

両サイトを `SHARE_MAX_SHAPES` (200,000 — `.board` インポートと同じ全盤面キャップ) へ。
`addMany` 等の per-op 500 キャップはそのまま維持 (ペースト等の正当 op が数百を超えることはなく、
細かい DoS ガードとして機能している)。

## 影響

- 500 図形超の盤面でも joiner が全図形を受領 (置換パス・merge パス双方)
- 回帰テスト: 空盤面への 600-shape スナップショット適用・非空盤面への 600-op merge を実動作で検証
  (旧 v1.7.49d テストは空盤面で実行されており merge パスに到達していなかった — 非空盤面に修正済み)
