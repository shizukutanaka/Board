# ADR-0785 — 初回起動サンプルボード (保存データが無い場合のみ)

- Status: Accepted (implemented)
- Date: 2026-11-12
- 関連: 競合監査 (2026-11-11) の訴求/オンボーディング P0、ADR-0004 (自己上書き保護 — 復元プロンプトとの順序)

## なぜ (Context)

初回起動時の Board は完全な白紙であり、新規ユーザーは「何ができるツールか」を
図形が1つも無い状態から推測しなければならない。競合監査はこの空白が転換率の
ボトルネックであるとして、初回サンプルの自動配置を P0 に挙げた。

一方で Board は local-first であり、既存ユーザーの保存データへの介入は
製品の根幹 (所有権) に触れる。サンプルは「データが存在しないこと」が
証明できる場合にだけ置けなければならない。

## 決定 (Decision)

起動シーケンスの末尾 (Persist.load → ADR-0004 バックアップ確認 → ハッシュ
インポート/招待 の後) で、以下の全条件を満たす場合に限り、小さなサンプル
ボードを通常の `addMany` op として1回だけ投入する (`_seedSample`):

1. `Persist.load()` の完了した読み取りで、DOC_KEY のドキュメントレコード
   自体が存在しなかった (`Persist._noDoc`)。空のレコードが存在する場合は
   「過去に使ったユーザーが全消去した」状態であり、投入しない。
2. 投入時点で図形が0件 (復元・インポートで何も入らなかった)。
3. 起動時 URL にハッシュが無い (共有リンク・招待リンクの訪問者は対象外。
   ハッシュは main 実行前に `_bootHash` へ退避して判定する)。

サンプルはタイトル文・付箋・ラベル付き矩形/楕円・矢印・使い方ヒントの6図形で、
文言は i18n (ja/en) 経由。投入は通常の op なので Undo・削除・編集がそのまま
効き、自動保存されればドキュメントレコードができるため二度と投入されない。

## 代替案 (Alternatives)

- ヘルプモーダルでのツアー表示のみ: 却下。実物の図形を触れる方が学習が速く、
  モーダルは初回の摩擦になる。
- 「図形0件なら毎回」投入: 却下。全消去したユーザーにサンプルが復活するのは
  所有権の侵害であり、条件1 (レコード不在) で厳密に初回へ限定した。
- サンプルを保存対象外のオーバーレイ表示にする: 却下。描画・同期・保存の
  全経路に特殊分岐が増え、通常 op で済む単純さを失う。

## 帰結 (Consequences)

- index.html が約 +1.8KB 増えたため、`test.mjs` の raw 上限 (暴走防止の
  ガードでありハード予算ではない) を ADR-0646 の前例に従い 544KB → 547KB
  へ引き上げた。
- 既知の制約: 初回に2つのタブを同時に開くと、保存 (500ms デバウンス) が
  伝播する前に両方が投入し、サンプルが重複しうる。害は重複した図形のみで、
  ユーザーが削除できる。通常の利用では起きない。
- IDB が使えない環境 (open 失敗時) では `_noDoc` が立たず、投入しない
  (安全側)。
